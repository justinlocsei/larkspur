# Larkspur

Larkspur is a zero-dependency TypeScript CLI library for building internal tools with nested commands, long-flag-only parsing, help, shell completions, and command discovery. The library ships from `src/`; development tasks live in `tasks/` and run via `./bin/larkspur`.

Node.js **22+** is required. Day-to-day development should use **Node 24** (matches CI defaults and npm 11 features).

## Repository layout

| Path | Purpose |
|------|---------|
| `src/` | Library source and unit/property tests (`*.test.ts`, `*.prop.test.ts`) |
| `tasks/` | Development CLI task definitions (`build`, `check`, `format`, `test`, …) |
| `bin/larkspur` | Symlink to `tasks/index.ts` — entry point for dev commands |
| `test/clis/` | Integration tests (shell completion harnesses, end-to-end CLI runs) |
| `dist/` | Build output (generated by `tsdown`; published to npm) |
| `.github/workflows/` | CI (`verify.yml` orchestrates check, package verify, and tests) |

Public API: `src/index.ts` exports `run`, default `C` factory, and `OperationalError`.

## Commands

Run `./bin/larkspur explore` to list every command and flag. Formats:

- `--format summary` — one line per command (rake `-T` style)
- `--format names` — flat list of usage titles
- `--format full` — detailed usage with flags (default)

### Task reference

| Command | Purpose |
|---------|---------|
| `build` | Build `dist/` with tsdown |
| `check` | Lint (Biome), format check (Biome + dprint), and `tsc --noEmit` |
| `check --only <check>` | Run a subset: `code`, `formatting`, or `types` |
| `format code` | Auto-format source (Biome import organize + dprint) |
| `format docs` | Format markdown documentation |
| `package verify` | Build, `npm pack`, install tarball in a temp consumer project, smoke test |
| `test all` | Unit, integration, and property suites in order |
| `test unit [--name <pattern>]` | Vitest unit project (`src/**/*.test.ts`) |
| `test integration [--name <pattern>] [--no-build]` | Vitest integration project (`test/clis/`) |
| `test property [--runs N] [--seed N] [--name <pattern>]` | fast-check property tests (`src/**/*.prop.test.ts`) |
| `explore [--format full\|names\|summary]` | Discover this CLI's commands |

Equivalent npm scripts exist for common tasks (`npm run check`, `npm test`, etc.) but prefer `./bin/larkspur` in docs and CI.

### Before finishing work

```sh
./bin/larkspur check
./bin/larkspur test all
./bin/larkspur package verify   # when packaging or publish-related code changed
```

CI runs the same pipeline on Node 22 and 24 (`.github/workflows/verify.yml`).

## Testing

- **Unit tests** sit beside source: `src/foo.ts` → `src/foo.test.ts`
- **Property tests** use the `.prop.test.ts` suffix and run in a separate Vitest project
- **Integration tests** live under `test/clis/` and may require **zsh** and **ncurses-term** (installed in CI)

Run a single file with `--name`:

```sh
./bin/larkspur test unit --name explore
```

After editing a source file, run its matching test file when one exists.

## Code style

- **TypeScript** with strict settings (`tsconfig.json`); use `.ts` import extensions
- **Biome** for linting and import organization; **dprint** for formatting
- Use `import type` for type-only imports (Biome enforces separated type imports)
- Sort keys alphabetically in plain object literals
- Add comments only for non-obvious logic
- Minimize scope — match existing patterns; don't refactor unrelated code
- Prefer extending existing helpers over new abstractions

## Working on the library

Larkspur CLIs are defined with the `C` factory (`src/factory.ts`):

- `C(description, handler)` — leaf command
- `C(description, flags, handler)` — command with flags
- `C.group(description, { subcommands })` — command group
- `C.flag(type, description, options)` — flag definition

Built-in commands (`explore`, `completions`) are injected by the runner — see `src/runner.ts`, `src/explore/commands.ts`, and `src/completions/commands.ts`.

Configuration types live in `src/types/config.ts`; validation in `src/validation.ts` and `src/config.ts`.

When adding commands or flags, update tests and shell completion expectations. Integration tests under `test/clis/completions.test.ts` cover bash and zsh output.

## Dependencies

All npm dependencies are **dev-only**. Dependabot manages **GitHub Actions** pins (SHA-pinned with version comments). npm updates are **manual**:

```sh
npm outdated
npm update          # within existing semver ranges in package.json
npm ci
```

`.npmrc` sets `min-release-age=7` (requires npm 11.10+). Major version bumps (e.g. TypeScript 7) are intentional changes to `package.json` — do not widen ranges unless asked.

## CI and security

- Workflows use `permissions: contents: read`
- Actions are pinned by commit SHA; Dependabot opens weekly update PRs
- CodeQL, secret scanning, and private vulnerability reporting are enabled — see `SECURITY.md`
- Do not commit secrets; do not disable hooks or skip CI checks unless explicitly requested
